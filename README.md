# MY EFT JOURNEY

타르코프 레이드가 끝난 뒤, 내가 돌아다닌 경로를 지도 위에 다시 그려 주는 외부 프로그램입니다.

- 파란 선: 이동 경로 (재생 슬라이더로 처음부터 다시 볼 수 있음)
- 주황 점: 킬 (마우스를 올리면 요약, 클릭하면 시각·상대·무기·부위·거리)
- 빨간 X: 탈출하지 못하고 사망한 위치
- 흰 점: 위치를 기록한 순간. 마우스를 올리면 그때 찍힌 스크린샷과 바라본 방향이 보입니다
- 회색 점: 온라인 레이드에서 게임 로그에 남은 서버 위치 기록 (참고용)

게임 메모리를 읽거나, 키 입력을 보내거나, 클라이언트를 건드리지 않습니다.
**게임이 스스로 남기는 파일만** 읽습니다.
Battlestate Games와 관계없는 비공식 팬 도구입니다.

| 무엇을 | 어디서 |
| --- | --- |
| 위치·바라본 방향 | 인게임 스크린샷 파일 이름 (게임이 카메라 좌표와 회전값을 파일명에 넣어 저장) |
| 맵, 레이드 시작·종료, 트랜짓, PvE/PvP | 게임 로그 폴더 (`...\Escape from Tarkov\build\Logs`) |
| 킬, 사망 정보 | 뷰어의 **편집**에서 입력 (킬 화면 OCR은 다음 단계) |
| 지도, 지명, 탈출구, 층 | [tarkov.dev](https://tarkov.dev) 공개 맵 데이터 |

## 사용법

Python 3.10 이상만 있으면 됩니다. 추가 설치는 필요 없습니다.

```bash
py -m eftjourney
```

처음 실행하면 로그 폴더와 스크린샷 폴더를 자동으로 찾아 스캔하고, 브라우저에 뷰어(`http://127.0.0.1:8765`)를 엽니다.
켜 둔 채로 플레이하면 5초마다 새 로그와 스크린샷을 확인하고, 레이드가 끝나면 목록에 바로 나타납니다.
진행 중인 레이드의 경로는 레이드가 끝난 뒤에 공개됩니다 (레이드 중 지도 오버레이로 쓰이지 않도록).

1. **먼저 스크린샷 키를 확인하세요.** 게임 기본값(`SysReq`)은 작동하지 않는 경우가 많습니다.
   게임 설정 > 조작 > 스크린샷에서 다른 키로 바꾸고, 눌렀을 때 오른쪽 아래에 알림이 뜨는지 확인하세요.
   F12는 Steam 스크린샷과 겹치고, PrtSc는 Windows 캡처 도구가 가로챌 수 있습니다.
2. 레이드 중에 그 키를 자주 누르세요. 누를 때마다 그 지점이 경로의 점이 됩니다.
   교전 직후, 건물 출입, 방향을 크게 바꿀 때 누르면 경로가 정확해집니다.
3. 레이드가 끝나면 뷰어에서 레이드를 고르고, 하단 **편집**에서 결과(생존/사망)와 킬을 입력합니다.
   킬 시각은 킬 목록 화면의 TIME(레이드 경과 시간, 예: `00:05:01`)을 그대로 넣거나 `5:01`처럼 분:초로 넣으면 경로 위 그 시점 위치에 점이 찍힙니다.
   도그태그를 챙기지 않은 PMC는 킬 목록에 `???`, 진영 `PMC`로만 나옵니다. 진영은 `PMC`로 두고, 레이드 통계의 BEAR·USEC 사살 횟수로 하나로 좁혀질 때만 그 진영을 고르세요.
   감염자처럼 이벤트 기간에만 나오는 적은 진영을 `기타`로 두고 메모에 적습니다.

### 뷰어 기능

- **재생**: ▶ 또는 Space, 속도 1×~60×, ←/→ 로 이전·다음 기록 지점
- **층**: 기숙사처럼 층이 있는 곳은 재생 위치의 높이에 맞춰 층이 자동으로 바뀝니다. 오른쪽 위에서 직접 고를 수도 있습니다 (지상 포함).
  지명도 그 층 것만 보입니다 (인터체인지 쇼핑몰 상점 이름은 2층·3층에서)
- **지도 180° 회전**: tarkov.dev 지도는 맵에 따라 익숙한 방향과 반대로 그려져 있습니다 (세관은 기숙사가 아래쪽). 체크하면 돌려서 봅니다.
  층 그림이 타일로만 있는 곳(세관 4층, 리저브 2~5층)은 회전 중에는 층 그림을 그리지 않습니다
- **따라가기**: 재생 위치를 따라 지도가 움직입니다
- **주의 N**: 위쪽 막대에 주황색으로 뜨면 마지막 스캔에 경고가 있다는 뜻입니다 (로그 세션을 읽지 못함, 스크린샷 폴더를 읽을 수 없음 등). 누르면 내용이 보입니다
- 트랜짓으로 다음 맵에 간 레이드는 결과가 자동으로 "트랜짓"이 됩니다. 레이드 도중 게임을 종료한 레이드는 끝난 시각이 추정치로 표시됩니다

### 명령

```bash
py -m eftjourney            # = run: 스캔 + 감시 + 뷰어
py -m eftjourney doctor     # 감지한 폴더, 로그 세션·스크린샷 수 확인
py -m eftjourney scan       # 한 번만 스캔
py -m eftjourney serve --open
py -m eftjourney demo       # 실제 기록 없이 화면을 볼 수 있는 데모 레이드 생성
```

폴더를 직접 지정하려면 `--logs`, `--screenshots`, `--data` 옵션을 쓰거나
환경 변수 `EFT_LOGS_DIR`, `EFT_SCREENSHOTS_DIR`, `EFTJOURNEY_DATA`를 설정하세요.

같은 데이터 폴더로 `run`이나 `scan`을 동시에 둘 이상 실행할 수는 없습니다 (서로 레이드를 덮어쓰므로, 두 번째는 안내만 하고 끝납니다).
이미 켜 둔 창이 있으면 그 창의 뷰어를 쓰세요. `serve`, `doctor`, `demo`는 함께 써도 됩니다.
켜 둔 창에는 레이드 저장과 함께, 새로 생긴 경고와 스캔 오류도 한 번씩 출력됩니다.

스크린샷이 2560×1440 PNG라 마우스 오버 미리보기가 무거우면 `py -m pip install Pillow`를 설치하세요. 작은 썸네일을 만들어 씁니다.

## 알아 둘 한계

- **경로는 스크린샷을 찍은 지점들을 직선으로 이은 것입니다.** 오래 안 찍은 구간(2분 이상)은 점선으로 표시합니다.
- 스크린샷 키를 자동으로 누르게 만드는 기능은 넣지 않았습니다. 온라인 레이드에서 키 입력을 자동화하면 매크로로 볼 여지가 있어서입니다.
- 게임 로그에는 레이드 결과(생존/사망, 사살한 상대, 탈출구)가 남지 않습니다. 결과와 킬은 직접 입력하거나, 다음 단계의 킬 화면 OCR로 채웁니다.
- 킬 점은 피해자 위치가 아니라 **사격 당시 내 위치(추정)** 입니다. 거리를 입력하면 그만큼의 점선 원이 함께 표시됩니다.
- 레이드 시간 밖(메뉴·은신처)에서 찍은 스크린샷과, 레이드 맵 범위를 75m 넘게 벗어난 좌표(스크린샷, 서버 위치 기록 모두)는 쓰지 않습니다. 메뉴에서 찍은 스크린샷에는 이전 좌표가 남을 수 있어서입니다.
- 쇄빙선은 tarkov.dev의 좌표 보정값이 지도 그림과 맞지 않아 위치가 어긋나게 그려집니다. 뷰어에도 참고용이라고 표시합니다.
- 1.3.0의 이벤트 맵(오염된 공장, 오염된 연구소)은 tarkov.dev에 지도가 없어 기본 공장·연구소 지도와 탈출구로 그립니다. 뷰어에도 실제와 다를 수 있다고 표시합니다.
- 끝 표시 없이 끝난 레이드(레이드 도중 게임 종료)는 게임이 꺼진 것을 확인했거나 게임을 다시 시작한 뒤에 보여 줍니다. 한 번 보여 준 레이드는 게임을 다시 켜도 그대로 있습니다.
- 로그 폴더를 찾지 못하면 스크린샷 시각만으로 레이드를 나눕니다. 예전에 읽은 로그 기록이 있으면 그 마지막 레이드 뒤에 찍은 스크린샷만 나눕니다.
  가장 최근 묶음은 마지막 스크린샷 뒤 15분이 지나고 게임이 꺼진 것을 확인한 뒤에 보여 줍니다 (게임을 계속 켜 두면 3시간 뒤에).
- 로그 형식과 스크린샷 파일명 형식은 1.3.0(2026-10-30)에서도 그대로인 것을 확인했습니다 (로그 세션 2개, 세관 레이드 스크린샷 99장).
  스크린샷 좌표가 tarkov.dev 지도와 같은 좌표계라는 것도 이 레이드로 확인했습니다 (첫 지점이 PMC 스폰에서 0.2m, 마지막 지점이 탈출구에서 7.9m).

## 데이터

이 폴더(소스)에서 실행하거나 편집 설치(`pip install -e .`)했으면 `data/`에, 일반 `pip install`로 설치한 경우 `%LOCALAPPDATA%\eftjourney\`에 저장합니다 (`--data`로 바꿀 수 있음).
스크린샷을 지운 뒤에는 이 폴더가 경로의 유일한 기록입니다. 가끔 폴더째 다른 드라이브나 클라우드에 복사해 두세요.
소스를 새로 받거나 일반 `pip install`로 바꿔 실행하면 저장 위치가 바뀌니, 이 폴더를 옮기거나 `--data`로 지정하세요.
옮기기 전에 `py -m eftjourney doctor`의 "데이터 폴더" 줄로 지금 쓰는 위치를 확인하세요.

- `data/raids/<id>.json`: 로그·스크린샷에서 만든 레이드 (스캔할 때마다 다시 만듦)
- `data/raids/<id>.edits.json`: 뷰어에서 입력한 킬·결과·메모 (스캔이 덮어쓰지 않음).
  손으로 고쳤다가 읽을 수 없게 되면, 스캔은 그 편집을 옮기거나 덮어쓰지 않고 경고로 파일 위치를 알려 줍니다
- `data/cache/logs.json`: 로그 파싱 결과. 공간을 비우려고 오래된 로그 폴더를 지우거나 게임을 다시 설치해도, 이미 읽은 레이드는 여기와 `data/raids`에 남습니다 (프로그램을 켜 둔 채 지워도 됩니다)
- `data/cache/shots.json`: 처음 본 스크린샷의 위치·시각 기록. 스크린샷 파일(장당 4~6MB)을 지워도 경로는 남습니다 (미리보기만 사라짐).
  확장자만 바꾼 같은 이름의 파일(PNG→JPG 변환)은 같은 스크린샷으로 봅니다.
  폴더 이름이 cache여도 이 파일은 지우지 마세요. 스크린샷을 지운 뒤에는 이 파일과 `data/raids`에만 위치가 남습니다.
  이 파일이 없어지거나 손상돼도 저장된 레이드 경로에서 위치를 다시 채웁니다 (손상된 파일은 지우지 않고 `shots.json.bad-<날짜-시각>`으로 옮겨 둠).
  항목 몇 개만 읽을 수 없게 바뀐 경우에도 그 항목은 그대로 두고, 경로에는 저장된 위치를 씁니다.
  레이드 시간 밖에서 찍은 스크린샷(메뉴·은신처)과 레이드 맵 범위를 75m 넘게 벗어난 위치는 경로에 없어서 다시 채우지 못합니다 (나중에 맵 데이터가 고쳐져도 돌아오지 않음)
- `data/cache/state.json`: 게임이 꺼진 것을 마지막으로 확인한 시각 (진행 중인 레이드를 가릴 때 씀)
- `data/cache/eftjourney.lock`: `run`·`scan`이 도는 동안 잡는 잠금 (빈 파일. 잠금은 프로그램이 끝나면 풀립니다)
- `data/cache/`의 나머지: tarkov.dev 지도 SVG, 썸네일 (손상된 파일은 자동으로 다시 받거나 다시 만듭니다)

모든 데이터는 이 PC에만 저장됩니다. 서버는 `127.0.0.1`에서만 열립니다.
외부로 나가는 요청은 이것뿐입니다:
- 뷰어 페이지가 Leaflet(지도 라이브러리)을 unpkg/jsDelivr에서 불러옴
- 서버가 tarkov.dev의 지도 SVG를 처음 한 번 받아 캐시함
- 브라우저가 tarkov.dev에서 지도 타일을 불러옴: SVG가 없는 맵(연구소·쇄빙선·미궁), 층 그림이 타일로만 있는 곳(세관 4층, 리저브 2~5층),
  그리고 지도 SVG를 받지 못했을 때 타일이 있는 다른 층(세관 2·3층 등)

로그에 있는 계정 ID, 서버 주소 같은 정보는 저장하지 않습니다.

## 지도 데이터와 라이선스

`eftjourney/data/maps.json`은 tarkov.dev 공개 데이터로 만듭니다.

```bash
py scripts/update_maps.py   # GitHub의 tarkov.dev maps.json + json.tarkov.dev API에서 다시 생성
```

- 맵 변환값·층·지명: [the-hideout/tarkov-dev](https://github.com/the-hideout/tarkov-dev) (MIT, 저작권 고지는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md))
- 탈출구·트랜짓·스폰·한국어 이름: json.tarkov.dev API.
  야간 공장·그라운드 제로 21+처럼 따로 목록이 있는 맵은 그 목록을 씁니다.
  그 목록에는 PMC/스캐브 구분이 없어, 같은 이름의 기본 맵 탈출구 중 가까운 것부터 짝지어 물려받습니다 (1m 넘게 떨어지면 갱신할 때 경고).
  맵 범위에서 75m 넘게 벗어난 항목(그라운드 제로에 섞여 있는 삼림 탈출구 2개)은 뺍니다
- tarkov.dev가 어느 지도에도 연결하지 않은 게임 위치는 `scripts/update_maps.py`의 `ALIASES`로 같은 지형의 맵에 붙입니다:
  1.3.0 이벤트 맵 `factory_event`(오염된 공장 → 공장), `laboratory_event`(오염된 연구소 → 연구소), 그라운드 제로 튜토리얼 `sandbox_start`.
  탈출구가 따로 없으므로 기본 맵의 탈출구를 보여 줍니다 (스폰은 API에 있으면 그 목록)
- 지도 그림(SVG): Shebuka 외 [tarkov-dev-svg-maps](https://github.com/the-hideout/tarkov-dev-svg-maps) 기여자, CC BY-NC-SA 4.0.
  상업적 이용 금지이며, 레이더·인게임 오버레이 같은 치트성 용도에 쓰면 라이선스가 철회됩니다. 이 프로그램은 레이드가 끝난 뒤의 리뷰에만 씁니다.
- 지도 타일(연구소·쇄빙선·미궁, 세관 4층, 리저브 2~5층): tarkov.dev가 제공하는 이미지입니다. 별도 라이선스가 공개되어 있지 않아 저장소에 포함하지 않습니다.

## 로드맵

1. ~~스크린샷 파일명 파싱 + 로그로 레이드 구분 + 지도 뷰어~~
2. 레이드 후 킬 목록·사망 화면 스크린샷 OCR → 킬·결과 자동 입력 (Windows 내장 한국어 OCR)
3. 화면 녹화 + 시각 오도메트리(VO)로 스크린샷 사이 경로 보간
4. 맵 이미지 직접 보정(기준점 3개 이상)으로 원하는 지도 이미지 사용

조사 내용(파일명 형식, 좌표 변환, 로그 구조, OCR 방안, 기존 도구)은 [docs/RESEARCH.md](docs/RESEARCH.md)에 정리되어 있습니다.
